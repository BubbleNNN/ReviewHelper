有 `n` 个节点，编号 `1..n`。`times[i] = [u, v, w]` 表示从 u 发到 v 的有向边，延迟 `w >= 0`。从节点 `k` 发出一个信号，返回**所有节点都收到信号**所需的最短时间；有节点收不到就返回 `-1`。

```python
network_delay_time(times, n, k) -> int
network_delay_time([[2, 1, 1], [2, 3, 1], [3, 4, 1]], 4, 2)   # 2
network_delay_time([[1, 2, 1]], 2, 2)                         # -1
```

- 可能有重边（同一对 u→v 多条边，取最小的那条起作用）和自环。
- `n` 可以到几千、边数到几万，要求 $O(E\log V)$。

场景：把集群看成一张带权图（NVLink 内的延迟小、跨机 IB 的延迟大），从一个 rank 广播参数，多久所有 rank 都能收到？这就是单源最短路里的最大值。

### 讲解

**Dijkstra + 最小堆**：

1. `dist[k] = 0`，把 `(0, k)` 放进堆；
2. 弹出堆顶 `(d, u)`。如果 `d > dist[u]`，说明这是过期的旧记录，跳过（**懒删除**）；
3. 否则松弛 u 的每条出边：`d + w < dist[v]` 就更新并把 `(dist[v], v)` 入堆；
4. 答案是 `max(dist)`，有 `inf` 就返回 -1。

**复杂度**：$O(E\log E)$，即 $O(E\log V)$。

**为什么要求非负权**：Dijkstra 的正确性依赖“堆顶弹出的点距离已经确定”，负权边会让已确定的点被更新。有负权用 Bellman-Ford（$O(VE)$）或 SPFA。

**易错点**：

- 节点编号从 1 开始。
- 没有“过期记录跳过”这一步结果也对，但会重复松弛，最坏变慢。
- 不要用 `visited` 在**入堆**时标记，要在**出堆**时标记。

> [!Q]
> **集合通信里真的是这样算延迟吗？** 不完全是。广播的实际完成时间还和带宽、消息大小、拓扑算法（ring / tree / 双二叉树）有关，常用 $\alpha$-$\beta$ 模型：$T = \alpha\cdot\text{步数} + \beta\cdot\text{字节数}$。最短路只对应“延迟主导、消息很小”的情况。

> [!Q]
> **全源最短路怎么做？** 稠密图用 Floyd-Warshall $O(V^3)$；稀疏图跑 V 次 Dijkstra $O(VE\log V)$。
