每个会议是半开区间 `[start, end)`（`start < end`）：一个会议在 `t` 结束，另一个在 `t` 开始，可以用同一间房。实现：

```python
min_meeting_rooms(intervals) -> int
assign_rooms(intervals) -> list[int]
min_meeting_rooms([[0, 30], [5, 10], [15, 20]])   # 2
assign_rooms([[0, 30], [5, 10], [15, 20]])        # [0, 1, 1]
```

`assign_rooms` 给每个会议分配一个房间号（从 0 开始），返回值按**输入顺序**对应。分配规则必须严格遵守：

1. 按开始时间从早到晚处理会议；开始时间相同的，输入下标小的先处理；
2. 处理一个会议时，所有**已经结束**（结束时间 `<= start`）的房间都是空闲的；
3. 有空闲房间就用**编号最小**的空闲房间；
4. 没有空闲房间就开一间新房，编号 = 当前已开房间数。

按这个规则，用到的房间总数恰好等于 `min_meeting_rooms`。

场景：把会议换成训练/推理任务，把房间换成 GPU 节点：任务有固定的起止时间，问最少要多少节点，以及每个任务放到哪个节点上。

### 讲解

**min_meeting_rooms**，两种写法：

- **最小堆**：按 start 排序，堆里存正在使用的房间的结束时间。来一个会议，先把堆顶 `<= start` 的弹掉（可能弹多个），再把自己的 end 入堆；过程中堆大小的最大值就是答案。
- **扫描线**：把 start 记作 +1、end 记作 −1，按时间排序，**同一时刻先处理 −1**（半开区间），前缀和的最大值就是答案。

**assign_rooms**：需要两个堆：

- `busy`：`(end, room)`，正在使用的房间；
- `free`：空闲房间号的最小堆。

每个会议先把 `busy` 里 `end <= start` 的房间全部挪进 `free`，然后 `free` 非空就弹出最小编号，否则开新房。

**复杂度**：$O(n\log n)$。

**易错点**：

- 半开区间要用 `<=` 判断房间已空闲；闭区间则用 `<`。
- 只从 `busy` 弹一个元素是错的：可能有多个房间在 start 之前都结束了，它们都应该进入 `free`，否则“编号最小”就选不对。
- 结果要按输入顺序返回，排序时记得带上原下标。

> [!Q]
> **房间数固定为 n，没空房时会议要往后推迟（LeetCode 2402），怎么改？** 没有空闲房间时，从 `busy` 弹出最早结束的房间（结束时间相同取编号小的），会议顺延到那个时刻开始，持续时间不变，新的结束时间 = 旧 end + 会议时长。这就是一个最简单的“任务排队 + 资源池”调度器。

> [!Q]
> **为什么选编号最小的空闲房间，而不是最早空出来的？** 两种都能达到最少房间数，区别在于资源局部性：总是复用小编号的房间，大编号的房间更容易长时间空闲，可以被回收或关机（类似把任务往少数节点上“装箱”，方便缩容）。
