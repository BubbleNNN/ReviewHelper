给定整数数组 `nums` 和整数 `k`，返回出现频次最高的 `k` 个元素。用两种思路各实现一遍：

```python
top_k_heap(nums, k) -> list[int]     # 计数 + 大小为 k 的最小堆
top_k_bucket(nums, k) -> list[int]   # 计数 + 按频次分桶
```

**输出顺序必须确定**：按频次从高到低；频次相同时按数值从小到大。

```python
top_k_heap([1, 1, 1, 2, 2, 3], 2)   # [1, 2]
top_k_bucket([4, 4, 1, 1, 2], 2)    # [1, 4]  频次都是 2，按数值升序
```

- `0 <= k <= 不同元素个数`，`k = 0` 返回 `[]`。
- 元素可以是负数。

场景：推理服务想知道哪些 system prompt 前缀最常出现，好决定 prefix cache 里优先保留谁。本质就是在大量 key 里求 Top-K 频次。

### 讲解

**计数**：`Counter` 或手写 dict，$O(n)$。下面只比较“从计数里取 Top-K”这一步，设不同元素有 $u$ 个。

| 方法 | 时间 | 空间 | 适用 |
|---|---|---|---|
| 全排序 | $O(u\log u)$ | $O(u)$ | 最好写，面试先说它当 baseline |
| 大小为 k 的最小堆 | $O(u\log k)$ | $O(k)$ | k 远小于 u；也适合流式数据 |
| 桶排序 | $O(n)$ | $O(n)$ | 频次上界是 n，能开得下 n+1 个桶 |

- **堆的方向**：维护一个大小为 k 的**最小堆**，堆顶是当前第 k 名。新元素比堆顶“更好”就替换堆顶。这里“更好”是先比频次再比数值，所以堆里存 `(freq, -num)`：频次小的先出堆，频次相同时数值大的先出堆。
- **桶排序**：`buckets[f]` 放频次为 f 的所有数，从 f=n 往下扫，桶内按数值升序取，凑够 k 个就停。
- **确定性**：真实面试题一般说“答案顺序任意”，但写服务的时候结果不稳定会让测试和缓存都很难调，所以这里规定了 tie-break。

> [!Q]
> **数据是流式的、内存装不下所有 key 怎么办？** 用 Count-Min Sketch 估计频次，加一个大小为 k 的最小堆维护候选（heavy hitters）；或者用 Misra-Gries / Space-Saving 算法，空间 $O(k)$，有误差上界。

> [!Q]
> **分布式场景下怎么求全局 Top-K？** 每个分片先求本地计数（不能只传本地 Top-K，否则会漏掉“每个分片都排第 k+1、但总和很高”的 key），按 key 哈希 shuffle 做全局聚合，再求 Top-K。近似场景下可以每片传 Top-k' (k' > k) 换带宽。
