CPU 每个时间单位执行一个任务或者空闲（idle）。`tasks` 是任务类型列表（大写字母），**同类任务两次执行之间至少隔 `n` 个时间单位**。

```python
least_interval(tasks, n) -> int     # 完成所有任务的最短总时间
schedule(tasks, n) -> list[str]     # 一个达到最短时间的执行序列，空闲用 "idle"
least_interval(["A", "A", "A", "B", "B", "B"], 2)   # 8：A B idle A B idle A B
schedule(["A", "A", "A", "B", "B", "B"], 2)         # 例如 ["A", "B", "idle", "A", "B", "idle", "A", "B"]
```

`schedule` 的结果可能不唯一，测试会检查：长度等于 `least_interval`；每类任务的出现次数和输入一致；同类任务的两次出现下标差 `> n`；末尾不能是 `"idle"`。

场景：同一张卡上的一类 kernel / 同一个 rank 的某种通信，执行完之后要等一段时间才能再跑（例如等资源释放、限流）。插入其他工作填满空闲，就是这题的贪心。

### 讲解

**公式**：设任务总数为 $N$，出现最多的任务出现 $M$ 次，出现 $M$ 次的任务有 $C$ 种：

$$\text{ans} = \max\big(N,\ (M - 1)(n + 1) + C\big)$$

直觉：把最多的任务排成 $M$ 个“框”，每框长度 $n+1$，最后一框只放出现次数等于 $M$ 的那几种。其他任务往框里的空位填；如果空位不够，说明根本不需要 idle，答案就是任务总数。

**构造序列（模拟）**：每个时刻从“已经冷却完毕”的任务里，选**剩余次数最多**的执行；没有可执行的就 idle。实现上用一个最大堆存可执行任务 `(-剩余次数, 任务)`，再用一个队列存冷却中的任务 `(可再次执行的时刻, -剩余次数, 任务)`。

**复杂度**：公式 $O(N)$；模拟 $O(\text{ans}\cdot\log 26)$。

**易错点**：

- 冷却是“中间至少隔 n 个”，即同类任务下标差 `>= n + 1`。
- 公式里的 $C$ 别漏，比如例子里 A、B 都是 3 次，最后一框有两个任务。
- 模拟时如果按字母顺序而不是剩余次数选任务，会得到更长的序列。

> [!Q]
> **为什么“优先选剩余次数最多的任务”是最优的？** 剩余最多的任务是瓶颈，越晚开始它越可能在最后被迫插 idle 等冷却。交换论证可以证明：任何最优序列都可以调整成每步选剩余最多的，不会变长。

> [!Q]
> **如果每类任务的冷却时间不同、执行时间也不同呢？** 公式就不成立了，一般用事件驱动模拟 + 优先级队列（按剩余工作量或截止时间排序），属于经典的带约束调度，通常是 NP-hard，工程上用贪心启发式。
